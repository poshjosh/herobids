- Runtime/session defaults can belong in the runtime descriptor or tool policy rather than operator config
- Secrets and infra wiring can stay in env or compose

**What I Would Change First**

1. Add a new worker block for worker scan interval, worker concurrency, and agent session health polling in schema.ts and default.yaml.

5. Keep vendor-standard OAuth and billing base URLs literal unless there is a concrete deployment reason to make them configurable.

**Important Boundary Note**

Not every row above should become an env var.

For this repo, the clean rule is:

- structured policy goes in default.yaml plus typed schema in schema.ts
- runtime/session knobs can live in runtime descriptor or tool policy if they are per-agent rather than per-operator
- env and compose stay mostly for secrets and infrastructure wiring

So for example:

- sandbox defaults and context diff policy belong in operator config or runtime defaults
- code_execute timeout and output cap are better as runtime/tool policy defaults than as environment variables
- API keys stay env-backed or secret-backed
- Docker host, image, and network can remain infra wiring
