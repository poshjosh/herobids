# FEEDBACK

**Recommended Tests**

- Add a sibling orderbook live-recovery smoke, not just more assertions in the current harness. The best target is a new script beside agent-trade-test.sh that forces the two crash windows Phase 3 cares about: after local submit persistence but before venue ack, and after venue ack but before local ack persistence. That directly exercises the remaining done-signal in 008-phase-3-live-execution-safety.md.
- Add a live minimal-limit lifecycle smoke. Either extend the TS harness with an order-type switch or add a dedicated script, but it should cover submit, open/resting state, timeout, cancel, partial/full fill, and post-timeout escalation. That is the exact contract called out in 008-phase-3-live-execution-safety.md and is not exercised by the current open-then-go-flat happy path in agent-trade-test.ts.
- Add a swap smoke for Jupiter and 1inch. I would make this a separate harness rather than bloating the current one, because the setup, secrets, and assertions differ materially. It should validate quote, execution, on-chain confirmation, restart with pending confirmation, ambiguous confirmation halt, and swap slippage alerts. That maps to the still-open T9/T10 work in 009-phase-3-live-execution-safety-tasks.md and 009-phase-3-live-execution-safety-tasks.md.
- Add a deterministic safety-lock functional test. Use a mocked or seeded adverse market path to trip stop-loss, cooldown, and circuit breaker, then assert the actor does not just look “down” but reports the correct safety state. That follows the unresolved API/status note in 005a-phase2-problems.md.
- Add an API/worker integration test for health and dead-letter visibility. Phase 4 says those runtime surfaces are now first-class, but the current E2E coverage only checks that a runtime health card appears, not that real degradation reasons and failed decisions surface correctly. The right targets come from 010-phase-4-config-validation-and-operational-polish.md and the current shallow UI check in 04-safety-alert-visible.spec.ts.
- Add a shared-wallet observational-variance integration test. This should inject an external balance delta after a confirmed swap and assert that startup continues and the journal emits observational variance, not authoritative drift. That is the current supported semantics in 005-phase-2-complete-swap-execution.md.
- Add a small matrix runner around the existing happy-path smoke. The current harness already covers open, close, and bookkeeping in agent-trade-test.ts, agent-trade-test.ts, and agent-trade-test.ts. The cheapest gain is to run that same flow across paper, shadow, and live for the currently supported orderbook venues before adding more complexity to it.

For the current harness specifically, I would keep agent-trade-test.sh as the happy-path orderbook smoke and avoid turning it into one giant Swiss-army script. A small update to parameterize order type and maybe a matrix wrapper is reasonable, but swap recovery and crash-window tests deserve sibling scripts because they are different products of failure.

**Gaps**

- Phase 3 is still the real open production-readiness area. The backlog explicitly says full recovery state-machine coverage and bounded swap-live parity remain in progress in 002-backlog.md, with #22 and #23 still marked in progress in 002-backlog.md and 002-backlog.md.
- The explicit unfinished slices are swap pending-confirmation recovery and swap crash-policy/execution-quality parity. Those are still marked in progress in 009-phase-3-live-execution-safety-tasks.md and 009-phase-3-live-execution-safety-tasks.md.
- Advanced limit-order lifecycle work is deliberately deferred. So test only the minimal safe limit-order slice now, not amend/replace or broad TIF semantics. That deferral is explicit in 008-phase-3-live-execution-safety.md.
- Dedicated or managed-wallet strict reconciliation is still deferred. Current swap semantics are shared-wallet observational only, as documented in 002-backlog.md, 006-re-alignment.md, and 005-phase-2-complete-swap-execution.md.
- There is still an unresolved design note around funded-wallet baselines and rebaselining. That is not just a test gap; it is a product decision gap in 005a-phase2-problems.md. Until that is decided, avoid writing any E2E that assumes strict shared-wallet holdings truth.
- There is also an unresolved semantics gap around returning explicit safety states like circuit-breaker-open and stop-loss-active instead of collapsing them into instance-not-running. That is called out in 005a-phase2-problems.md and is worth addressing before you invest in UI-level safety-state journeys.
- Several Phase 2 out-of-scope items remain intentionally deferred: swap websocket fill streaming, swap-specific unrealized PnL in the risk path, cross-chain or richer routing semantics, and dedicated-wallet strict reconciliation. Those are listed in the out-of-scope section of 005-phase-2-complete-swap-execution.md.
- Phase 4 also leaves deliberate deferrals: no automated retry orchestration for dead-lettered decisions, no actor-health dashboard UI, no paper synthetic reconciliation, and no direct-agent shadow/live execution outside the running actor lifecycle, all in 010-phase-4-config-validation-and-operational-polish.md.
