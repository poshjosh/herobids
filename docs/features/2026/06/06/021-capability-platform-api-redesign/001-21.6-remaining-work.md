It already registers these redesigned surfaces:

Gaps still relevant to Step `21.6`:

- `apps/api/src/routes/connections.test.ts`
- `apps/api/src/routes/capabilities/trading.test.ts`

- `apps/api/src/routes/credentials.test.ts`

Rule:

1. extend `apps/api/src/__tests__/functional/helpers.ts` to register missing redesigned surfaces
2. extend `apps/api/src/__tests__/functional/capability-model.functional.test.ts` with negative-path lifecycle coverage

4. audit mocked route tests and keep only the narrow logic they uniquely cover

6. update `tests/e2e/helpers.ts` only where journeys need clearer agent-first setup helpers
7. strengthen `tests/e2e/journeys/08-mission-control-capability-reflects.spec.ts`
8. audit `tests/e2e/journeys/04-safety-alert-visible.spec.ts`

## Minimum Browser UAT Baseline

1. sign up and create an agent from the primary agent-first flow
2. land on agent detail and observe a capability readiness state without being forced through bot-first setup
3. create or select a reusable platform connection
4. bind the trading capability to the agent
5. observe readiness transition to usable state
6. trigger the primary capability action from the agent surface
7. verify mission control reflects the resulting agent state honestly

Where the product still lacks a public binding-creation UI, seed the binding row deliberately and document the reason in the relevant journey.
