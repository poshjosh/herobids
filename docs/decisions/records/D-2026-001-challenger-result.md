## 4. Weakest assumption and strongest unconsidered option

- **Weakest assumption:** that hibernated time would be unbilled and that the 10,000 residents are all paying at the seed rate (W4). It drives P7 and C4 but not the final recommendation. A second contender is that the first wall is Redis (W1): the Postgres wall is much earlier.
- **Strongest option not considered:** hibernate only agents that are over their hard billing limit and not trading (W2).

## 5. Verdict

Stands with changes: (1) correct E11/P4 to say reminders and messages gate on agent status, not container state (B1); (2) add the Postgres connections-per-agent versus `max_connections` wall to E9, A-23, measurement 3, the triggers and OD-04, and re-check the C3/C8 ratings (W1); (3) add the billing-suspended-agents option, or make it the first Stage 2 class (W2); (4) grade the $43k figure as an upper bound, show the cost ceiling for feasible node sizes, and add the break-even standby fraction (W3, W4); (5) keep the exact gate phrase, add a second G4 line for OD-12, and require an owner direction on OD-12 before the Stage 1 build (W5); (6) mark experiment item 4 as non-staging, state what the stub test cannot cover and define its pass/fail (INV-O2, W6, W11); (7) add the single-flight wake prerequisite for INV-S1 and complete the register updates, including the Traderton reference for OD-13 (INV-S1, INV-P2, W12).
