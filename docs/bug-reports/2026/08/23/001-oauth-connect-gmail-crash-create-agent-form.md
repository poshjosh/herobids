# 001 — "Connect Gmail" button crashes in create agent form due to undefined ref

- **Status:** OPEN
- **Severity:** HIGH
- **Date:** 2026-08-23
- **Discovered:** User clicks "Connect Gmail" in the ProviderSetupForm opened from the create agent page (`/agents/new`); browser console shows `ReferenceError: dailyLossLimitAutoRef is not defined`.
- **Environment:** local (docker compose, localhost:8080)
- **Component:** `apps/web/src/features/agents/AgentsPage.tsx`

## Summary

When creating a new agent via the standard form at `/agents/new`, clicking "+ Add connection" opens the `ProviderSetupForm` modal. After selecting Gmail and clicking "Connect Gmail", the `onBeforeOAuthRedirect` callback throws an unhandled `ReferenceError` because it references `dailyLossLimitAutoRef` — a variable that does not exist. The actual ref declared in the component is `dailyMaxLossPctAutoRef` (line 335).

The error silently kills the OAuth flow: no redirect occurs, no error banner is shown to the user, and from the user's perspective "nothing happens."

## Reproduction

1. Navigate to `http://localhost:8080/agents/new` (standard create agent form, not guided setup).
2. Click "+ Add connection" in the connections section.
3. In the provider setup modal, select "Gmail" from the dropdown.
4. Click the "Connect Gmail" button.
5. **Expected:** Browser redirects to Google OAuth consent screen.
6. **Actual:** Nothing happens. Console shows:

```
AgentsPage.tsx:772 Uncaught ReferenceError: dailyLossLimitAutoRef is not defined
    at onBeforeOAuthRedirect (AgentsPage.tsx:772:33)
    at handleOAuthConnect (ProviderSetupForm.tsx:201:7)
```

## Root Cause

In `AgentsPage.tsx`, the `CreateAgentFlow` component declares:

```ts
const dailyMaxLossPctAutoRef = useRef(false);  // line 335
```

But the `onBeforeOAuthRedirect` callback (line 772) references the non-existent name:

```ts
onBeforeOAuthRedirect={() => {
  const { pendingFiles: _pendingFiles, ...serializableIntent } = intent;
  saveCreateAgentOAuthDraft({
    step,
    intent: serializableIntent,
    nameIsAutoGenerated,
    dailyLossLimitAuto: dailyLossLimitAutoRef.current,  // <-- WRONG NAME
    maxHoldDurationManuallySet: maxHoldDurationManuallySetRef.current,
    policyManuallySet: policyManuallySetRef.current,
  });
}}
```

The ref was likely renamed from `dailyLossLimitAutoRef` to `dailyMaxLossPctAutoRef` at some point, and this callsite was missed.

The same stale name is also used in the OAuth return restore logic (line 381):

```ts
dailyLossLimitAutoRef.current = restoredDraft.dailyLossLimitAuto;  // <-- ALSO WRONG
```

This second instance would crash when returning from a successful OAuth flow (if it ever completed), preventing draft restoration.

## Impact

- Users cannot connect Gmail (or any OAuth provider) from the standard create agent form. The OAuth flow is completely blocked.
- The AI-guided form and the connections page are unaffected (they use different code paths).
- The edit agent modal (`EditAgentModal.tsx`) is unaffected (it uses its own `saveEditAgentOAuthDraft` with a different set of fields).

## Fix

Replace both references to `dailyLossLimitAutoRef` with `dailyMaxLossPctAutoRef`:

1. Line 772: `dailyLossLimitAuto: dailyMaxLossPctAutoRef.current,`
2. Line 381: `dailyMaxLossPctAutoRef.current = restoredDraft.dailyLossLimitAuto;`

Also consider whether the `CreateAgentOAuthDraft` interface field name (`dailyLossLimitAuto`) should be updated to `dailyMaxLossPctAuto` for consistency — though this is cosmetic since the draft is ephemeral (sessionStorage, cleared on restore).
