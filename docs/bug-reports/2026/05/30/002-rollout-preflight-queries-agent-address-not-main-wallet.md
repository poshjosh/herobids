# Bug Report: Pre-flight clearinghouseState Queries Agent Address Instead of Main Account

- **Status:** CLOSED
- **Severity:** Medium
- **Date:** 2026-05-30
- **Summary:** The rollout script's pre-flight account check queries the wrong Hyperliquid address. It used `HYPERLIQUID_API_KEY` (the agent/API wallet address) as the `user` parameter for `clearinghouseState`, which always returns $0 equity and 0 positions because the agent wallet holds no funds.

## Root Cause

In `scripts/shell/rollout-stage-b.sh`, the pre-flight HTTP call was:

```bash
-d "{\"type\":\"clearinghouseState\",\"user\":\"$HYPERLIQUID_API_KEY\"}"
```

`HYPERLIQUID_API_KEY` is the *agent wallet address* — a separate Ethereum address generated by Hyperliquid as an API key. It has no funds. The main trading account lives at a different address (`HYPERLIQUID_WALLET_ADDRESS`).

Consequences:
- **Equity check always saw $0** — The equity value returned was always `0` for the agent address. The check compared against the string `"0"` exactly, and since Hyperliquid returns `"0.0"`, the `die` was never triggered. This masked the bug: the check was silently passing while inspecting an empty wallet.
- **Open positions always showed 0** — Even if the main account had open positions, the pre-flight check would report 0 open positions and would not warn the operator, potentially allowing a new instance to start without the expected drift warning.

## Fix

**`scripts/shell/rollout-stage-b.sh`** — Changed the `clearinghouseState` query to use `HYPERLIQUID_WALLET_ADDRESS`:

```bash
-d "{\"type\":\"clearinghouseState\",\"user\":\"$HYPERLIQUID_WALLET_ADDRESS\"}"
```

## Regression Tests

This bug is in `scripts/shell/rollout-stage-b.sh` — a shell script. The fix (changing the `clearinghouseState` query from `HYPERLIQUID_API_KEY` to `HYPERLIQUID_WALLET_ADDRESS`) is verified by shell syntax check (`bash -n`) and manual integration test. No unit test is applicable for a bash variable substitution.

## Files Changed

- `scripts/shell/rollout-stage-b.sh`

## Verification

- `bash -n scripts/shell/rollout-stage-b.sh` passes (SYNTAX OK)
- Pre-flight now correctly reports the main account's equity and open positions

## Notes

- This bug was coupled with bug #001 (missing `walletAddress`): the `HYPERLIQUID_WALLET_ADDRESS` env var introduced by #001 is exactly what the pre-flight should query.
- The equity check still uses a naive string comparison (`== "0"`). If Hyperliquid changes their response format (e.g. returns `"0.00"` instead of `"0.0"`), the check would again silently pass. A safer comparison would use `awk` or `node` to check if the value is numerically zero.
